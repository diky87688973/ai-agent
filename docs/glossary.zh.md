# 术语

项目中有一些自定义术语，含义固定。本页是这些术语的**唯一定义处**。

## 用词约定

| 英文 | 中文 | 用法 |
|---|---|---|
| Round | 轮 | 一条用户消息及其后的 assistant / tool 消息 |
| Turn | 回合 | 一条输入触发的全部活动，直到宿主进入终态 |
| Pass | 趟 | 模块链从头到尾跑一遍 |
| Session | 会话 | 持久会话标识及其事实流 |
| Conversation | 对话 | 会话内交换的消息内容 |
| Fact / Event | 事实 / 事件 | 事实是事件落盘后的形态 |
| Write gate / Quality gate | 写盘门控 / 质量门禁 | 运行期写盘拦截 / CI 与评审门禁 |
| Web UI / Web entry | Web 界面 / Web 入口 | 浏览器界面 / HTTP 服务入口 |
| Tool round-trip | 工具往返 | 一次模型调用及其工具执行与结果 |

## 结构

**模块链**
内核的行为结构。宿主反复按固定顺序运行一组模块，每个模块只实现 `execute(ports) -> Outcome`。顺序为 `输入 → 待发送队列插入 → 压缩 → 模型 → 工具`。见[架构](architecture.zh.md)。

**装配根**
`agent/app.py`。唯一同时引用五层的文件，负责构建 `AppContext` 并登记服务。它不属于任何一层。

**双轨**
决策链与事件总线两条互不干扰的轨道。决策链参与控制流，事件总线只做通知。见[架构](architecture.zh.md)。

**端口**
`Ports`。模块操作外界的**唯一**通路。模块拿不到上下文对象，也不能直接操作文件、网络或工具实现。

## 数据

**事实**
已经发生、落盘后不可改写的一件事。单位是事件（`Event`），形状为“类型 + 载荷”。

**事实流**
某会话全部事实按发生顺序组成的 append-only 日志，一行一条，落在 `<data_root>/sessions/<cid>.raw`。

**投影**
事实的实时视图。界面看到的 SSE 流就是投影，不是另一份真相。

**契约**
跨层传递的数据对象，冻结在 `core/` 内。跨层只传契约对象，不传裸 dict。

**轮（Round）**
以一条 `user` 消息起轮，含其后的 assistant 与 tool 消息。上下文按轮为单位保留、压缩和划定边界。

**块（Chunk）**
上下文里带名字的一段；近期记忆块容纳对话轮。共五块，顺序固定。见[上下文管理](subsystems/context.zh.md)。

**回合（Turn）**
一条输入引发的全部活动，直到没有任何模块要求续行，或模块链终止。

**趟（Pass）**
模块链从头到尾跑一遍。一个回合通常包含多趟。

## 控制

**Outcome**
模块执行结果的唯一形状，**只带控制信号**：`ok` / `next` / `halt` / `suspend` / `stopped`。数据不走它。

**续行**
`Outcome.next` 表示“本趟做完了，但还需要再跑一趟”。宿主的退出条件之一就是“没有任何模块要求续行”。

**挂起**
`Outcome.suspend` 表示“需要外部输入，交回控制权”。不阻塞线程。

**门控**
住在决策链上的拦截规则，能阻止主流程。订阅者无法阻止主流程，执行顺序也不确定，因此门控不走事件总线。

**写盘四步协议**
写类工具的最强规则：预览 → 确认 → 凭 `confirm_id` 提交 → 重读。见[工具](subsystems/tools.zh.md)。

**confirm_id**
一次写预览的标识。提交时只凭它，写参数由门控从快照恢复，模型不重传。同一路径再次预览时，或未提交快照达到上限时，旧 id 会被挤掉并失效。

**review**
写盘的前置动作。模型必须给出基于实际审阅的结论与验证证据，才能解锁预览。

## 上下文

**保留窗口**
末尾若干用户轮优先保持原文的范围，宽度由 `full_user_rounds` 决定；前面没有可压缩空间时，压缩仍可能覆盖这些轮次。

**摘要**
已被压缩的历史轮次概括而成的文本，落在“记忆文件”块。

**压缩**
把越界轮次压成摘要的动作。触发条件是估算 token 超过阈值。

**估算 token**
不是精确计数，而是按字符类型与消息结构推算的值。图片按固定值计。

## 会话

**会话 id（cid）**
会话标识。必须匹配 `^[A-Za-z0-9_-]{8,128}$`，新会话用 UUID4。它同时用作落盘文件名，因此这道校验也是防路径穿越的边界。

**待发送队列（conversation queue）**
会话级的消息暂存区。会话忙时，用户与 Agent 消息先排队，回合结束后逐条投递，一条消息一回合；标记插入的消息在下一个安全的模型趟进入上下文。

**协作网格（mesh）**
让多个会话互相投递消息的机制：名册、运行占位与忙闲原子投递。

**运行态登记**
回答“某会话的回合是不是正在跑”的落盘记录。判定需要心跳未过期**且**记录里的进程还活着。

**跨进程锁**
按日志文件加的排它锁。同会话的“记偏移 → 追加 → 回滚”是读改写，进程内锁挡不住别的进程，会静默丢行。

## 壳层

**适配层**
`agent/shell/classic_adapter/`。在经典界面与内核之间做双向翻译，是处理行为差异的首选落点。

**内联打包**
把界面资源全部内联进一个 HTML，运行时零额外请求。

**SSE**
界面与服务之间的单向事件通道。每帧带会话 id 与序号，断线重连靠序号续传。

**可见根**
文件查看器与补全能看到的目录范围，由 `--fs-root` 指定。
