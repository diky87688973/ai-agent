# 上下文压缩工具（暂停）

**状态：** 暂停，尚未实现。

## 1. 目标

模型主动选择低价值轮次，提供压缩摘要；上下文在下一趟模型请求前按摘除清单移除这些轮次。阈值压缩继续保留为兜底。

与阈值压缩的区别：

```text
工具压缩：模型按当前价值选择任意轮次
阈值压缩：超限时按前缀整体兜底，不判断内容价值
```

## 2. 边界

- 工具可以选择任意历史轮次，不要求连续前缀。
- 只保护最后一轮；更早轮次都可以被选择，包括曾经高价值的轮次。
- 事实日志只增不减，摘除只作用于派生上下文视图。
- 工具调用只记录压缩请求；实际摘除与摘要注入发生在下一趟模型请求前的压缩阶段。
- 摘要由模型在工具入参中提供，查询接口不生成摘要。
- 阈值压缩移除的轮次进入同一摘除清单。

## 3. 轮次 ID

轮次 ID 取自该轮第一条 `input_claimed` 事件的 `_seq`：

```text
round_id = "r_" + str(_seq)
```

模型可见形式是 user 消息内容前缀：

```text
[r_102] 用户原文
```

规则：

- 前缀只在装配模型请求时添加，不写入会话事实。
- 只给真实用户输入开头的轮次加前缀；系统通知、子会话消息、工具回灌不伪造轮次 ID。
- UI 读取事实日志中的原始内容，不展示前缀。
- 老轮次前缀稳定；新轮次只追加尾部，不引入每趟变化的前置索引。
- 模型直接看到 ID 与同轮正文，`compress` 入参复制该 ID。

## 4. 上下文结构

```text
[系统提示词][skills][摘要][知识库][r_101 a][r_102 b][r_103 c][当前轮][后缀]
```

压缩 b 之后：

```text
[系统提示词][skills][摘要 + b 的摘要][知识库][r_101 a][r_103 c][当前轮][后缀]
```

a、c 的正文保持原样；b 的正文不再进入派生视图。

## 5. 压缩工具

工具名：`compress`。

入参：

```json
{
  "round_ids": ["r_102"],
  "summary": "b 轮中的最终约束、结论、矛盾裁决与未完成事项"
}
```

工具描述必须说明：

- 列出的轮次会从后续模型上下文中移除。
- `summary` 会作为 system 摘要消息进入上下文前置区域。
- 只允许选择当前仍存在且不是最后一轮的轮次。
- 入参 ID 必须来自当前 user 消息前缀。

工具只记录请求，不直接修改事实日志。

## 6. 压缩阶段

`CompressModule` 在每次调用模型前执行：

```text
读取待处理压缩请求
  → 校验 round_ids、最后一轮、摘要格式
  → 将轮次 ID 写入 removed_rounds
  → 从全量派生视图移除对应轮次
  → 将 summary 追加到摘要区
  → 写入 context_compacted 事件
  → 重新计算有效上下文

仍超阈值
  → 执行前缀阈值压缩
  → 被压缩轮次 ID 同样写入 removed_rounds
```

工具请求在下一趟模型请求前生效；当前已经发出的请求不回改。

## 7. 视图与持久化

- `removed_rounds`：已摘除轮次 ID 的集合并集，单调增加。
- `summaries`：工具摘要与阈值摘要各自成为 system 摘要消息。
- `context_compacted` 事件持久化 `removed_rounds` 与摘要；恢复时重建视图。
- 已经被移除的轮次不能再被选择。
- 同一轮次重复请求按已移除处理，不重复写入摘要。
- 物理事实与原始会话记录保留，便于恢复与审计。

## 8. 保护与校验

```text
最后一轮不可移除
当前轮中的 tool call / tool result 不作为独立轮次
round_id 不存在 → 拒绝整个请求
summary 为空 → 拒绝
summary 超过长度上限 → 拒绝
摘要写入 system 区域，不覆盖系统提示词、skills、知识库
```

校验失败不改 `removed_rounds`，不写摘要，不推进阈值压缩。

## 9. KV 缓存

- 轮次 ID 前缀属于对应 user 消息；老消息内容不随新轮次变化。
- 不引入每趟重写的前置轮次索引。
- 工具压缩修改派生视图；公共前缀从第一个被移除轮次之后失效，这是压缩本身的代价。
- 阈值压缩同样从压缩点之后失效，不叠加额外索引失效。
