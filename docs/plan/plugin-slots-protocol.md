# 插件 2.0 插口协议

本文是插件 2.0 的协议与设计约束唯一正文：术语、灵魂、节点字段、片段、依赖、覆盖和生命周期只在这里定义。

当前实现、热插拔步骤、已完成配套功能、尚未落地的设计和验证入口统一见 [实现与验证](plugin2-hotplug.md)。本文不重复维护工具、路由、事件和节点的完整清单，也不保存阶段验收数字。

## 术语

三个概念各只占一个位置，不许串。下面每条例明定义、是否可派生、承载字段、判据。

### 主插口

```text
定义    独立模块子树的根插口：该路径存在后代
可派生  是。纯拓扑事实，不需要任何字段
承载    无字段。禁止另设布尔声明同一件事
判据    有后代 ⇒ 是主插口；无后代 ⇒ 不是。没有第三种
        与 kind、owner、关键性均无关
```

补一句边界：有后代但 kind 不允许持有子级，是**两条独立断言同时成立**——
它在拓扑上是主插口，同时它违反「能持有子级」。前者成立不豁免后者。

### 关键插口

```text
定义    失败策略：该节点构造失败时是致命还是可丢弃
        致命 ⇒ 抛错上抛，让父装配一起失败
        不致命 ⇒ 留痕后丢弃这一条
可派生  否。是意图：同一 kind 在 A 模块里致命、在 B 模块里可丢，结构上看不出来
承载    当前节点层无字段；现役节点构造统一失败，不沿用旧贡献 API 的 critical 通道
判据    构造失败时的行为可观测：上抛，或留痕后跳过
```

节点层为何暂无字段：现役装配的失败策略是统一的——任一节点构造失败即抛
`SlotAssemblyError` 并逆序释放已构造节点，不存在「按节点区分致命与否」的需求。
给 `SlotSpec` 加 `critical` 属新增能力，需单独走新增能力检查，不得顺手加。
因此这里写明：节点层**没有**字段承载「关键」，不得用任何含义含糊的布尔冒充。

### 能持有子级

```text
定义    该节点能不能挂子节点
可派生  是。结构能力，不需要任何字段
承载    无字段
判据    kind ∈ {container, module, ui-slot} 或 children ≠ none
        唯一权威函数 holds_children(spec)，定义在 agent/core/slot_spec.py
```

### 通用条款：可派生者不得有字段

凡能由路径或 kind 现算得到的，不许另给字段再声明一遍。
两个来源声明同一事实，就是 0.6 禁止的第二本账。

判据：

```text
新增字段前先回答：该值能否由路径 / kind / children 算出
能算出 ⇒ 不得加字段，加一个算一个违反
算不出（意图、外部输入）⇒ 才允许字段，且名字必须专指该意图
```

## 0. 灵魂

运行时只有一棵插口树，由两个来源在内存合并而成。

```text
静态片段   内置核心：kernel / host / boot / shell / tools
           仓库内固定，随代码发布
动态片段   plugins/<插件名>/ 各自携带
           插件自己声明暴露什么、依赖什么

扫描 plugins/ → 收集片段 → 校验冲突 → 内存合并成一棵 → 每轮取快照
```

下面八条是判据，不是原则声明。每条给出可检验的说法；不满足判据即违反。

### 0.1 唯一实体

运行期只有一棵插口树，不存在「插件」与「树」两套并行结构。

判据：

```text
任意时刻取「已声明路径的集合」，有且只有一个来源
装配、绑定、快照、查询读到的节点集合逐项相同（路径集合相等，不是数量相等）
删除任一插件目录后，树上不再出现它的任何路径
```

### 0.2 两个来源，一个结果

静态片段与动态片段是同一种数据，只在磁盘位置不同。

判据：

```text
两类片段的解析走同一个函数；字段、校验、报错文案逐条相同
一个路径的声明方由 origins 回答，与它来自哪个文件无关
每个装配代只合并一次；运行期仅在显式热插拔或重载请求时读取片段，构造候选代
当前回合继续使用原有代；文件变动本身不修改已建成的树
```

### 0.3 轮次快照

每轮取一次快照，轮内只读。

判据：

```text
同一轮内多次取快照返回同一对象
轮内新增节点、换实现、改 requires 一律不生效
启停与片段改动在下一轮可见
快照对象不可写（写操作抛 TypeError）
```

热插拔的读取租约覆盖回合和插件 HTTP 请求。存在活跃读取者时延迟发布，空闲时立即应用。
候选构造与登记失败时恢复旧身份、模块和登记，旧代继续有效。实现与回归见
[实现与验证](plugin2-hotplug.md)。宿主服务的启动覆盖沿用 §0.8，状态型宿主服务的在线迁移不由插件热插拔执行。

内核模块与宿主服务的实现替换统一在进程重启后生效；插件自身贡献与运行时资源走上述热插拔代发布。不因实现文件位于 plugins 目录就把内核或宿主覆盖升级为在线迁移。

### 0.4 零侵入

加一个插件 = 加一个目录。

判据：

```text
新增插件目录后，不改动 plugins/ 之外的任何文件，插件能力即完整可用
宿主代码里不出现任何具体插件名作为分支条件
去掉该目录后，宿主启动、装配、门禁全部照常通过
```

### 0.5 全在包内

插件能力全部落在 plugins/<名>/。

判据：

```text
该插件的声明、实现、资源、界面文件路径全部以 plugins/<名>/ 为前缀
包外不出现该插件的任何文件
包外不出现只在「该插件存在时」才被使用的宿主分支
```

### 0.6 唯一权威

运行期不许有与树并行的第二本账。

判据：

```text
注册表、白名单、绑定表都能由树现算得到；删掉它们再算，结果相同
不存在第二处保存「某路径由谁实现」的地方
同一事实不在两个容器里各存一份（判据：改一处而另一处不变，即为双写）
```

白名单必须从声明派生，不得手写第二份：`SPEC_FIELDS` 由 `fields(SlotSpec)` 现算，
声明类里那个字段定义是字段名的唯一出处；能派生的值一旦写成字面量集合，
加字段时两处就会分叉（解析器拒、门禁放）。

### 0.7 声明即构造

声明是唯一事实源。

判据：

```text
节点声明里写有什么，就构造什么；代码里不存在第二份清单来补充或删减
声明为 declarative 的节点返回声明本身，不另存副本
构造结果与声明逐节点对应：每个声明路径都有值，或明确不参与本作用域
```

### 0.8 可替换性

任何非冻结插口都必须能被换实现。声明为插口却不能换实现，它就不是插口。

#### 8.1 非冻结 ⇒ 可换实现

判据：

```text
对树上任一非冻结节点注入替换实现，装配成功，且该位置取到的是替换后的实现
冻结是唯一例外，且冻结必须真的生效（见 8.1.1）
不存在「某些 kind 能换、某些 kind 不能换」的白名单
```

8.1.1 冻结作用于整棵子树：

```text
frozen 节点自身与其全部后代都不可被覆盖
对冻结子树内任一节点的覆盖一律拒绝，报错含该节点路径与 frozen 字样
判定在装配主干之前完成，不依赖调用方自觉
```

#### 8.2 内核与插件一视同仁

判据：

```text
覆盖求值不读声明方；__host__ 节点与插件节点走同一分支
覆盖一个内核 service 节点与覆盖一个插件节点，行为与报错文案同构
```

#### 8.3 主插口被替换 ⇒ 子树跟随失效

判据：

```text
主插口以 replace_subtree 覆盖后，其全部后代不再出现在有效视图里
这些路径不被构造：查询逐个报「不存在」，且没有任何节点拿到覆盖方实现
失效凭路径前缀一次算完，与 disable 的级联同一算法
```

8.3.1 覆盖不得声明后代：

```text
覆盖只换实现，不产生节点；覆盖 row 的 path 就是被覆盖路径本身
row 里出现被覆盖路径的后代 path ⇒ 拒绝，报错含「覆盖不得声明后代：<path>」
要在子树下增加节点，走片段 slots / provides（声明层），不走覆盖
```

#### 8.4 子插口可独立替换

判据：

```text
子节点以 replace 覆盖后，父节点与它的兄弟节点实现不变
父节点照常构造一次，且读到的是子的新值
替换只改实现；改 path / kind / scope / children 属结构变更，装配期拒绝并指明
该字段属于结构变更，须走下一轮快照
```

#### 8.5 替换发生在树上

判据：

```text
有效视图 = 声明 + 覆盖 现算得到；不落盘、不进全局、同输入同输出
覆盖在求值后被丢弃：除求值函数外没有任何读取点
装配、绑定、快照只读有效视图；读原始声明做构造只允许存在于有效视图构造内部
```

#### 8.6 插口判据

判据：

```text
对每个非冻结节点注入可识别桩并跑装配，任一节点装配失败即判「假插口」
该检查是门禁的一部分，不靠人工抽查
```

字段白名单门禁通过不等于本条成立：它只证明「节点字段集合闭合」，
不证明任何节点可被换实现。不得把「门禁绿了」当成第 8 条的证据。

### 0.9 反例

以下每一条都构成对第 8 条的违反：

```text
声明了插口，但装配直接读原始声明做构造，不走有效视图
  → 覆盖声明写了也不生效，8.5 与 8.6 同时被破坏

只有插件能换实现，内核节点覆盖被拒或被忽略
  → 违反 8.2；可替换性退化为插件特权

主插口被替换，子插口仍拿旧实现继续构造
  → 违反 8.3；旧实现与替换方并存，等于两套实现同时活着

覆盖声明里写后代节点，把覆盖当声明用
  → 违反 8.3.1；声明层与实现层混同，provides 与 mode 退化成两套并行机制

把同一份实现摊给子树每个节点以表达「跟随替换」
  → 违反 8.3；凭空造出一对多映射，正是 0.6 禁止的第二本账

frozen 只冻自己、不冻子树
  → 违反 8.1.1；冻结一个容器等于形同虚设，子节点照样被换

替换机制存在但无调用方，装配主干从不使用
  → 违反 8.6；插口不可换实现即为假插口
```

合并是一次性的内存操作，不写盘、不生成中间文件。磁盘上是多份片段，运行时只有一棵树。

## 1. 节点契约

### 1.1 字段唯一来源

机器可校验的字段源是 `agent/core/slot_spec.py::SlotSpec`；`SPEC_FIELDS` 从 dataclass 字段推导，不能另维护手写白名单。文档说明字段含义，不承担第二份字段清单的维护责任；新增或移除字段必须同步说明和负向测试。

| 字段 | 含义与约束 |
|---|---|
| `path` | 唯一节点身份，归入唯一根 `app` |
| `kind` | 构造与绑定契约，取值见下一节 |
| `factory` | `module:attribute` 实现引用；纯声明节点不使用 factory |
| `requires` | 参数名到依赖路径的映射，不允许悬空或依赖成环 |
| `owner` | 所有权与清理归属；不替代声明来源 `origin` |
| `order` | 同一父节点下的顺序；显式相同 order 发生冲突 |
| `scope` | `app` 或 `session`，决定实例所属生命周期 |
| `frozen` | 冻结自身及整个后代子树，覆盖不得绕过 |
| `children` | 子级策略 `none`、`keyed` 或 `fixed` |
| `fixed` | `children=fixed` 时允许的子名 |
| `props` | 声明载荷；含义由对应 kind 的消费契约确定，不是任意 metadata 袋子 |
| `method` | HTTP 路由的明确方法 |

`mode` 只出现在覆盖声明；启停由插件清单控制；文件级版本不放进节点。未知字段和已退役 `metadata` 明确拒绝，不静默忽略。`master`、`subtree`、`exposed`、`cache`、`phase` 等派生事实不另设节点字段；不存在独立 `paths` 声明表，子级策略归节点自身。

### 1.2 kind、工厂与消费契约

允许的 kind 集合由 `KINDS` 定义。`ctx` 总是第一个参数，`requires` 的键作为命名参数注入；容器类还接收已构造的直接子节点 `children`。返回对象的生命周期由装配账本负责。

| kind | 构造产物与绑定方向 |
|---|---|
| `container` | 组合直接子节点；无 factory 时产物为子节点 tuple |
| `module` | 内核阶段对象，提供 `run(pass_ctx)`；按 scope 构造 |
| `service` | 宿主服务对象，默认 app 作用域 |
| `provider` | 提供上下文、提示词或模型目录等契约值，目标由 `props.target` 声明 |
| `tool` | 提供工具名和 execute 的工具对象 |
| `route`、`http-route` | HTTP 处理器；方法与 HTTP 路径由声明明确给出 |
| `event` | 事件处理器；订阅宿主常量或通过 requires.event 引用插件事件声明 |
| `event-channel` | 插件自有事件定义；无factory，名称由完整节点路径派生 |
| `assembly-hook` | 上下文拼装钩子 |
| `executor` | 工具提交执行器 |
| `setting` | `SettingDecl` 面板或字段，save/load 回调由所属插件实现 |
| `runtime` | 插件持有的进程内运行时对象，退出时释放 |
| `ui-slot` | 可被填充的声明式 UI 插口，属于容器类 |
| `ui-action`、`ui-control`、`ui-tool-shell` | 动作、控件和工具卡外壳声明 |

四种 `ui-*` 不运行 factory，声明本身就是产物。其余工厂按 kind 约定调用，具体签名以 `slot_assembly._invoke` 为准：容器类为 `factory(ctx, children, **requires)`，其他为 `factory(ctx, **requires)`。

### Web UI 组件替换

`web_ui` 提供两个可替换的 `ui-control`。插件在自己的 `plugin-slots.json`
用 `overrides` 的 `mode: "replace"` 指向目标路径，在 `props.script` 或
`props.scripts` 声明自己的相对脚本路径。有效目录从覆盖片段确定脚本归属。
脚本执行时调用 `window.aiAgentClassicComponents.register(path, implementation)`。

| 插口路径 | 实现契约 |
|---|---|
| `app/shell/web-ui/chat/messages/process` | `mount(host)` 将容器挂入消息区并返回 `{node, body, title}`。宿主将过程节点追加到 `body`。`finish(view, status, count, elapsedMs)` 管理完成后的折叠行为，可用 `elapsedMs` 展示回合总耗时。运行中或历史记录缺少耗时时，该值为空。可选 `dispose(view)` 释放监听与其他资源。 |
| `app/shell/web-ui/left-panel/sessions/list` | `render(host, context)` 展示目录，`context.page(key)` 读页快照，`load(key, reset)` 取页，`mutate(body)` 整理目录，`open(id, title)` 打开会话。可选 `dispose(host)` 释放资源。页键为 `recent`、`pinned`、`projects` 或项目 ID。 |

文件、展示协议产物和确认卡挂在消息主线。折叠组件只接收过程节点。
替换插件卸载后按有效目录恢复默认实现。禁用过程插口时，过程内容平铺。

`provider` 的已登记目标是 context-source、prompt-section、mode-tail、assembly-hook、model-catalog。目标及额外字段由 `SlotBinder` 校验：prompt-section 必须给出 section，路由必须给出 method 与 `props.path`，不得按节点末段猜测 HTTP 地址。新增目标要同时增加契约、绑定实现和负向测试，不能借 props 绕过登记。

工厂引用有两种来源：宿主 `agent.<module>:<attribute>`，插件 `<relative.module>:<attribute>`。插件相对模块必须解析在声明来源的实际插件根内；`plugin:make` 仅表示该目录下 plugin.py 的 make，不是另一种特殊注册机制。工厂可通过 BuildContext 的 spec、config、built/depend、resolver、boot_config、data_dir、plugin_meta 获取已声明环境；不虚构 `ctx.requires` 或把 ctx.config 说成插件配置文本。

### 1.3 覆盖与有效视图

| mode | 设计语义 |
|---|---|
| `replace` | 同一路径更换实现，保留节点形状和原有子树 |
| `replace_subtree` | 更换主实现，旧后代从有效视图消失、不再构造 |
| `disable` | 本节点及后代不进入有效视图 |
| `extend` | 保留默认调用并追加实现 |
| `wrap` | 包装默认调用，控制调用前后 |

**模式枚举不等于装配链已经实现。** 当前有效装配视图支持 replace、replace_subtree、disable；extend/wrap 的组合构造仍被 `effective_view` 明确拒绝。后两项保留为设计语义，未完成项见实现文档，不以“可解析”冒充“可装配”。

覆盖只更换实现，不产生声明节点，也不能修改 kind、scope、children、fixed 等结构字段。冻结子树拒绝覆盖。同一路径多个独占替换、replace 与 replace_subtree 并存、disable 与其他模式并存均为配置冲突；被整棵禁用或替换的子树下不得再声明覆盖。

`effective_view` 只产出一份有效 SlotConfig，消费方只读该视图；被删除的后代不得继续构造。覆盖输入求值后不再成为运行期第二套权威。

### 1.4 作用域与失败

- app 节点属于进程装配；session 节点登记为模板，在对应会话装配生命周期内构造、释放，不跨会话共享可变实例。
- module 缺省为 session，其他节点缺省为 app；依赖先在当前会话实例中解析，再查询 app 级节点，不跨会话取值。
- 主插口、子级能力、关键失败策略是三个概念，不能由同一个布尔字段承担，定义见术语。
- 配置错误使用 SlotConfigError；构造或绑定失败使用 SlotAssemblyError，并包含节点路径及原始原因。
- 任一构造失败停止后续构造并逆序释放；释放本身失败要留痕并继续释放其他资源。
- 启动与代切换入口不接受部分绑定结果。底层绑定器可收集单项错误，但上层必须使整次应用失败。

## 2. 片段、归属与合并

### 2.1 文件与职责

| 文件 | 唯一职责 |
|---|---|
| 仓库根 `plugin-slots.json` | 静态插口与所有权前缀授权 |
| `plugins/<name>/plugin-slots.json` | 插件 slots、provides、overrides 与 subagent_tools 声明 |
| `plugin-meta.json` | 插件身份、版本、描述、图标和配置入口元数据；Python 入口可不存在 |
| `plugins.ini` 及剖面 | 插件启停、顺序和外置目录来源，不另存能力清单 |
| `plugin-config.ini`、`settings-schema.json` | 插件配置值与编辑表单契约，不承担节点声明 |
| 插件 ui、css、图标等文件 | 插件私有静态资产，目录边界校验后送达，不逐个作为装配节点 |

plugin.py 提供声明引用的工厂，不通过 register(ctx)、ctx.add_*、set_runtime 等另建贡献清单。旧多通道注册、旧路径种子表和双树过渡不作为现役协议。

### 2.2 slots、provides、overrides 的区别

- slots 声明实际节点。插件可声明自身 `app/plugins/<name>/...` 子树，也可声明静态 owners 授权的前缀；插件不能给自己授予外部前缀。
- provides 填充已声明且接受子级的挂载点。先收齐所有 slots，再校验 provides；不能靠扫描顺序碰巧成功。
- overrides 对已有节点求覆盖有效视图，不代替 slots 或 provides 新增路径。
- origin 是声明/实现来自哪个插件；owner 是目标节点的所有权与清理归属。provides 的 owner 由挂载点授权决定，origin 仍是贡献方，两者不能混同。
- 加载器补齐中间祖先：插件自身前缀内的 owner 属插件，共享前缀属宿主；已存在的祖先不得被隐式改写，且必须允许持有子级。
- children=none 拒绝贡献，keyed 接受任意合法子名，fixed 只接受 fixed 列表中的子名。

最小插件片段示例：

```json
{
  "version": 1,
  "slots": [
    {
      "path": "app/plugins/example/tools/example_tool",
      "kind": "tool",
      "factory": "plugin:make_tool"
    }
  ]
}
```

### 2.3 合并和构造顺序

```text
静态片段 + 按剖面选中的动态片段
  → 解析相同字段与契约，记录 owners、origins 和实际 plugin_roots
  → 收齐节点与贡献，补齐合法祖先
  → 校验路径、所有权、子级、order、事件名、依赖与覆盖冲突
  → 求唯一有效视图
  → 拓扑排序 requires，按 kind 注入依赖和直接子级
  → 构造并登记释放账本
  → SlotBinder 登记到消费接口
  → 发布装配代和冻结快照
```

路径重复、未知字段、悬空依赖、依赖环、同父同显式 order、工厂不可解析、越过插件根或未经授权的声明都必须拒绝。错误应指出路径和来源，不能静默选一份。挂载点插件停用时依赖它的贡献休眠，恢复后重新求值，不将临时停用误当成永远不存在的挂载点。

### 2.4 清单、外置来源与读取时机

默认清单发现目录自带片段，显式禁用优先。独立清单是完整剖面，不能意外加载本机未列出的普通插件；显式自动装载标记的行为见实现。继承剖面先展开再装配。

清单 path 对应的真实根通过 plugin_roots 传递，片段、工厂、元数据和资产使用同一来源；在执行工厂前校验路径信任策略。插件与同级本机代码同等信任：能依赖声明、归属和来源记录，不能据此声称有恶意代码沙箱或签名校验。

启动和显式重载读取片段；文件改变本身不修改已发布代。回合和插件 HTTP 请求持读租约，存在活跃读者时排队，空闲时应用。内核和宿主实现更换在进程重启后生效，插件自身贡献支持安全边界热插拔；详细切换顺序和请求终态只在实现文档维护。

### 2.5 消息展示扩展契约

消息展示能力复用 `ui-tool-shell`，展示类型由插口节点的 `props.renderer` 声明。类型为 1–80 位小写字母开头的字母、数字、下划线、点或短横线，整个有效目录中唯一；非法类型与重复声明在绑定阶段拒绝，不发布部分成功的装配代。

前端 `aiAgentShell.displays.register(type, render, owner)` 只绑定实现，不声明能力；类型必须存在于服务端有效 UI catalog 且 owner 匹配。实现返回销毁函数或空值；撤销绑定、替换修订、关闭会话及卸载时释放资源。取消声明后不得继续呈现或调用该实现。声明与实现的唯一权威分别为插口有效目录和该目录约束下的实现绑定，不建立第二份插件能力清单。

渲染类型可用 `props.editable:true` 声明支持视图编辑，该字段必须是布尔且附属于 renderer。默认模式固定为 `view`，模型数据不决定编辑模式。公共宿主持有每个面板的瞬时模式，提供唯一切换入口及 `context.mode.get()/set(mode)/subscribe(listener)`；插件只投影该模式。未声明编辑能力时拒绝切入 `edit`，非法模式及失效代的调用拒绝。模式不是业务事实，不写入工具结果；新修订和页面重载恢复 `view`。模式订阅随渲染代释放，监听器异常成为局部可见错误，不影响其他面板。

工具经既有 ToolPipeline 返回 `display`，面板文档为 `{version:1,id,revision,operation,type,title,summary,data}`。`id` 在会话内稳定，`revision` 为正整数，`operation` 为 `upsert` 或 `remove`；具体工具负责输入 schema、修订连续性与幂等校验。宿主只投影既有工具事实，按会话和面板 ID 选择最高修订，不新增业务存储。未知版本、缺失实现和局部渲染失败须显示可读状态，原始事实保留。

公共载体、事实投影与视图状态服务归 `agent/shell/web/`；组件算法、schema、私有样式与依赖归插件包。宿主不得根据具体插件名或图表类型分支。前端本地视图状态与业务事实分离；向模型回传必须由用户明确操作，经既有消息入口及权限路径，不允许面板隐藏发起工具调用。

补充公共宿主契约属于架构变更，必须提供负向测试和独立插件验证；契约具备后，新增同类插件只增加包内声明和资产。宿主实现替换要求重启，插件声明与实现遵守既有安全边界热插拔。插件代码属于可信本机代码；上述 owner 检查不构成恶意插件隔离沙箱。

## 3. 插件作者与复核清单

新增插件只新增自身目录及清单项，不修改核心分支。插件身份来自 meta；有工厂才需要对应 Python 模块。一次工具贡献对应独立声明，依赖、所有权、路由与 UI 落点明确；UI、配置、图标、主题和释放逻辑随插件归属。

复核时逐条检查：

1. 满足 §0 的唯一树、两来源一结果、轮次只读、零侵入、包内资产、唯一权威、声明构造和可替换性。
2. 所有节点归 app 根，所有 requires 存在且无环；冻结作用于整个子树。
3. 声明、覆盖和子级策略不混用；owner、origin、scope 各有唯一含义。
4. 构造或绑定失败整体失败，旧运行代可恢复，资源逆序释放；卸载不遗留路由、事件、工具或 UI 登记。
5. 提示词与上下文贡献声明语义目标，tail 只在请求末尾，空文本不生成空段；不能通过额外注册通道制造第二来源。
6. 工具调用仍经 ToolPipeline 和质量门控；没有插件侧绕过门控的未登记目标。
7. 内核或宿主覆盖要求重启；不能仅因代码放在 plugins 里就对宿主做在线状态迁移。
8. 数量和完整清单由片段、catalog、事件常量和生成器读取，不在协议手写固定数值冒充门禁。
9. 新增或变更契约有负向测试，按实现文档的验证入口执行；未落地设计不能写成已实现。


## 插件自有事件

插件在自身命名空间声明事件定义，无需修改core.event_name：

```json
{"slots":[{"path":"app/plugins/example/events/completed","kind":"event-channel"}]}
```

事件定义必须位于app/plugins/<owner>/events/<name>，name为小写字母开头的字母、数字、下划线或短横线；仅支持app作用域、叶节点，无factory和requires。现有片段归属规则拒绝未经授权在他人命名空间声明；重复定义沿用路径冲突检查。事件定义本身是装配产物SlotSpec，不另建可变事件目录。

订阅方声明event节点，requires.event引用该定义；工厂接收event参数（SlotSpec）并返回处理函数。绑定器按event.path订阅既有EventBus，卸载由登记disposer退订。发布方工厂同样可通过requires取得定义和既有event_bus服务，用Event(type=event.path,data=...)发布纯通知；不新增发布旁路或第二条贡献注册接口。载荷契约归事件提供插件，不增加通用业务schema数据库。

```json
{"slots":[{"path":"app/plugins/listener/on_completed","kind":"event","factory":"plugin:make_handler","requires":{"event":"app/plugins/example/events/completed"}}]}
```

缺失或非event-channel引用、session级订阅均拒绝。强依赖提供方不能在依赖方仍启用时被单独移除，候选代失败并保留旧代；先关闭依赖方再关闭提供方。UI挂载点休眠规则不替代强依赖校验。事件定义重新启用后，依赖方按正常装配重新登记。

宿主事件仍按core.event_name常量校验，路径必须命中唯一常量；未声明的任意字符串仍然拒绝，避免把拼写错误当成自定义事件。该约束属于受信插件的声明一致性检查，不是恶意本机代码的权限沙箱。
