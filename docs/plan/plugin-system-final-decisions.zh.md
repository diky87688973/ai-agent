# 插件系统最终实施决策

## 1. 启动顺序

```text
宿主
→ 内核
→ 基础插件：基础设置 → 基础 UI
→ 其他插件
→ GUI / WEB / CLI / HEADLESS
```

基础设置先注册设置面板和设置项。  
基础 UI 后注册页面结构、区域和宿主专属控件。  
其他插件启动时注册自己的路径。

## 2. 前端注册

前端注册发生在插件加载时，不在页面运行时新增路径。

```text
插件加载
→ 注册 UI 路径
→ 页面读取注册结果
→ 按路径渲染
```

页面只渲染已注册路径，不提供运行时注册入口。

## 3. 设置

所有设置保存后立即生效。

```text
保存
→ 校验
→ 持久化
→ 热应用
→ 校验运行状态
→ 成功
```

任一设置应用失败：

```text
整次保存回滚
旧值保持
返回失败
```

禁止：

```text
保存后重启
保存后刷新页面才生效
写盘成功但运行状态未更新
显示“重启后生效”
```

设置包括：

```text
基础设置
界面设置
模型设置
插件设置
主题设置
插件启停
```

## 4. 资产归属

基础 UI 的 HTML、CSS、JS 全部归基础 UI 插件。

```text
plugins/web_ui/
  ui/shell.html
  ui/css/
  ui/js/
```

宿主只保留：

```text
启动
鉴权
HTTP
静态传输
插件系统运行环境
```

基础设置 UI 归基础设置插件：

```text
plugins/base_settings/ui/
```

主题、模型、知识库、AI 说话、视觉、Skills、Rules、自动更新的 UI 归各自插件。

## 5. 简单注册模型

```text
插件注册路径
路径决定插口
谁注册，谁拥有
```

不引入额外 owner 字段、运行时注册接口、Provider 替换层或设置端口抽象。

注册项直接包含：

```text
路径
类型
名称/图标
数据
点击处理函数或保存函数
```

宿主只负责渲染、分发和热更新。

## 6. 最终约束

```text
没有旧插件形态
没有中途兼容层
没有双路径
没有重启生效
没有插件逻辑散落在宿主
```
