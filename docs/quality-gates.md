# Quality gates and budgets

The current values for gates and budgets are listed below. The single source for the numbers is `scripts/quality_budgets.py`; after a budget constant changes, `docs/complexity.md` is kept in sync by the generator and the checker.

## 1. Budget summary

| Budget | Constant | Current value | Constraint | Notes |
|---|---|---|---|---|
| Acceptance script skips | `ACCEPTANCE_SKIP_BUDGET` | 1 | May only decrease | Set **separately** from the allowlist; a larger allowlist does not relax the cap |
| Coverage floor per package | `COVERAGE_FLOORS` | 10 packages (25%–90%) | May only increase | `agent/core 85`, `agent/mechanisms 80`, `agent/capabilities 75`, `agent/shell 70`, `agent/entry 60`, `agent/gui 25`, `agent/update 60`, `agent/subagent 85`, `agent (top-level) 90`, `plugins 60` |
| Complexity over threshold | `MAX_FILE_LINES` / `MAX_FUNCTION_LINES` / `MAX_FILE_FUNCTIONS` | 800 / 80 / 40 | Hard failure | No exemption table; exceeding any one item fails |
| Same-layer private imports | `SAME_LAYER_PRIVATE_BUDGET` | 0 | May only decrease | Importing `_` symbols across modules in the same layer; over budget fails |

Constraints in `check_complexity.py`:

- Any file, function, or per-file function count over its threshold → **fail**;
- `docs/complexity.md` differing from the current scan → **fail** (generated-doc drift).

### 2.1 Coverage (post)

The coverage step validates the `.coverage` file published by `run_coverage.py` and compares `COVERAGE_FLOORS` per top-level package. How the data is produced (CI runs it in the 3.12 matrix):

```bash
python scripts/run_coverage.py        # run all unit tests and publish .coverage
python scripts/check_coverage.py
```

`run_coverage.py` writes the `coverage run` output to `.coverage.tmp.<pid>` first, then holds the lock and atomically replaces it with `.coverage` via `os.replace`: a reader sees either the complete old file or the complete new file, never data half-written by a parallel collection. Writers and readers of the same artifact serialize through `.locks/coverage.lock`.

Without a `.coverage` file the step returns `2` (SKIP), visible in the CI output and not counted as a pass; the same applies when the data file is rewritten by an external process during the check — no conclusion is drawn from partial data.

### 2.2 Local JS event audit

Re-rendered lists — the kind that rebuild their nodes on every refresh — do not bind an event listener per item. Events bind once on the top-level `document`, and the target is resolved by bubbling plus `closest()` / `contains()`. Per-item binding creates a new batch of listeners on every rebuild; when a node is removed, listeners still referenced by a closure leak with it.

`scripts/scan_js_events.py` scans JS/HTML under `agent/` and `plugins/` and grades every `addEventListener`, `onXxx=` property assignment, and inline HTML event from static evidence:

| Grade | Meaning | Needs review |
|---|---|---|
| `per-item` | Inside a loop body (judged by brace balance, not indentation) | yes |
| `leak-risk` | Global listener on a render path with no paired removal | yes |
| `render-path` | Bound to a persistent target inside a render function | yes |
| `inline` | Inline HTML event; cannot be delegated | yes |
| `delegated-ok` | Container root plus `closest` / `contains` target resolution | no |
| `global-once` | Module-level or one-time-initialized global listener | no |
| `guarded-ok` | Same function carries an `_xxxDelegated` / `dataset.bound` guard | no |
| `ephemeral` | Target created by `createElement` / the `el()` factory and destroyed with the node | no |
| `ok` | Any other binding on the element itself | no |

The audit only prints findings; it never fails the run. The criteria are a static approximation, so `render-path` and `leak-risk` still need model confirmation (for example, an `ensureXxx()` with an early-return guard actually binds once).

Two fields:

- **Paired removal** requires the same target, event, callback, and capture. If any one differs, the listener cannot be removed and counts as unpaired — a named callback means "can be removed", not "was removed".
- **Anonymous** is shown in the report only and does not affect grading.

Run it separately:

```bash
python scripts/scan_js_events.py                    # all
python scripts/scan_js_events.py --only per-item    # one grade only
python scripts/scan_js_events.py --path composer    # one directory only
```

`scripts/ci.py` calls it automatically at the end of a local run. Remote CI does not run it: grading needs business semantics and no model is available there; the script itself also exits early when `GITHUB_ACTIONS=true`.

### 2.3 Parallel CI

Only one `ci.py` may run per repository at a time. The entry point takes `.locks/ci.lock` first (created atomically with `mkdir`); when the lock is held, it waits up to `--lock-wait` seconds and then fails. A lock left by a force-killed holder is reclaimed by PID liveness. `--force-lock` tears the lock down once the holder is confirmed gone. The `.locks/` directory is not version-controlled.

## 3. Drift and rollback

1. **Constants before docs**: `python scripts/gen_complexity_md.py`; editing Markdown alone is rejected by `--check`.
2. **Budget increases** record each new hit and its reason; the script output is the audit trail.
3. **Over-threshold items**: split until under the threshold; no exemption entries exist.
4. **Negative cases** live in `tests/test_gate_negative.py`: each covered gate gets a minimal input that must fail and a valid input that must pass, run against temporary files rather than the real repository.

## 4. Unwired items

None. Coverage, config drift, generated-doc checks, the generated `ci.yml`, and concurrency contention are all in `scripts/ci_steps.py`; `python scripts/ci.py --list` and `ci.yml` have the same step set.
