# 动手规则

## P0 红线：没有明确修改指令，禁止任何写操作

本条是写入门槛，优先于其他规则中的执行选择。已获得修改授权后，再由架构规则决定怎么改。

- 用户提问、质疑、讨论、征求方案、询问原因，都不是修改授权。
- 用户说“走某方案吧”“能不能改成…”这类建议或询问，也不是修改授权。
- 只有用户给出**强烈**的明文确认行动信号，即用户输入中明文指令带有“改 / 修 / 删 / 加 / 提交 / 推送 / 重启 / 执行”等动作指令，才允许写文件、重启进程、提交代码。未有明文指令时禁止一切意图猜测认为用户需要改。
- 不确定是否授权时，只回答，不动手。
- 违反此条视为最高级事故。

工程复核的触发、只读边界与全量 CI 例外，按 [PROJECT_CHECK.md](PROJECT_CHECK.md) 执行。
