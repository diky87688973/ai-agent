# 架构第一原则

## P0 **强制遵守**架构第一原则，优先级排在所有P0规则之前，违规则视为最大事故，停止一切行动。

AI写不好代码是因为不懂遵守规矩，先学规矩，所有代码必须在规矩之内。

## 1. 适用

适用于任何项目、任何语言和任何技术栈。
规则只约束结构、职责、依赖、归属、状态和代码表达，不绑定具体目录名、框架、协议或业务。

技术栈可以不同，判据不变：

```text
高内聚
零非法耦合
职责单一
边界清晰
归属正确
零苟且
注释简洁
```

## 2. 效力等级

```text
MUST     不变量；违反即阻塞合并
SHOULD   默认做法；偏离必须在评审中说明理由和验证方式
MAY      可选；同一项目内保持一致
```

无法机器判定的 MUST 必须进入评审清单。
可以机器判定的约束必须写成检查，不靠记性维持。

## 3. 高内聚

MUST：

```text
一个模块只围绕一个主要变更轴
一个文件只承担同一职责
同一业务规则只实现一次
模块名能说明它为什么存在
删除该模块时，不会牵连无关模块
```

判据：

```text
修改一个业务规则，只应改动一个主模块
新增一个同类能力，只应新增文件加一处注册
同一个规则在两个文件各写一份，必须合并
一个模块同时处理输入、持久化、展示和调度，必须拆分
```

SHOULD：

```text
文件、函数、类的大小设上限
超过上限必须拆分，不留豁免清单
```

## 4. 零非法耦合

“0 耦合”不表示禁止依赖。任何系统都有依赖。
本规则要求 **0 非法耦合**：

```text
依赖方向合法
层内无环
没有跨层私有依赖
没有双向依赖
没有跨模块共享可变状态
没有为当前用例绕过既有入口
```

MUST：

```text
依赖方向必须写清楚，并由检查强制执行
依赖图必须检查强连通分量，不能只检查成对互引
公开边界之外的私有符号不得跨模块导入
同一可变状态不得在多个模块各留一份
跨模块只能通过公开接口、事件、注册表、服务或窄契约
```

判据：

```text
把依赖图跑一遍强连通分量，环必须为 0
删除一个模块的公开入口后，其他模块不应还能通过私有路径使用它
一个模块的字段名不应成为另一个模块的字符串契约
```

SHOULD：

```text
依赖方向文档与代码一致
搬动目录或包名后，规则仍然生效
规则以包路径为键，不以目录展示名为键
```

## 5. 职责单一

MUST：

```text
门面只做组合和形状转换，不承载业务规则
路由只做分派，不承载业务动作
适配层只做协议转换，不持有业务状态
仓库只负责持久化归属，不负责调度和展示
消息模块只负责投递，不负责生命周期
调度模块只负责调度，不负责业务处理
展示组件只负责自己的状态与渲染
```

判定：

```text
一个函数的说明需要列出三个以上“顺带做”的动作，职责已经混杂
一个模块同时读写两个以上资源域，先确认是否越权
一个组件通过全局坐标操作另一个组件的布局，属于越界
```

## 6. 边界清晰

MUST：

```text
跨边界只走公开契约
外部输入在信任边界处校验
内部实现细节不得进入外部契约
配置、事件、API 字段必须有唯一归属
错误必须在边界处被分类，不得静默降级
```

校验要求：

```text
路径：解析后与根目录比对，不用字符串前缀
命令：参数列表传递，不拼 shell
配置：失败时指出文件、键和原因
标识符：校验通过后才用于路径、查询或命令
```

禁止：

```text
用异常控制正常流程
用宽泛捕获掩盖不变量破坏
把失败包装成成功
用一个全局开关替代边界设计
```

## 7. 归属正确

每个新增或移动资产必须回答：

```text
为什么属于这个模块
其他模块为什么不能拥有
能否由既有字段派生
唯一注册点在哪里
谁创建、谁读取、谁清理
失败和卸载时影响谁
是否会被错误打包、发布或注入
```

MUST：

```text
源文件归能对其行为负责的模块
运行态数据归对应服务
插件私有资产归插件自身
公共资产归公共层并登记
生成物由生成器产出，并由检查重生成比对
新增工具必须同时声明注册条件、依赖、生命周期、关闭路径和失败行为
```

禁止：

```text
孤儿文件
重复副本
无注册点资产
旧路径资产被新代码静默忽略
同一状态在注册表、对象属性和存储中各存一份
```

## 8. 零苟且

以下形态不得合入：

```text
死代码、无调用点导出
临时旁路、测试专用后门
无版本边界和退出条件的兼容层
宽泛异常把不变量错误变成业务失败
返回失败但调用方仍按成功处理
用临时对象、临时数据或假状态伪造正式注册
为当前用例新增无依据默认值
只改测试断言掩盖失败
失败回滚只做一半
```

新增失败路径必须回答：

```text
谁捕获
是否留痕
返回什么错误
调用方如何识别
部分写入如何回滚
重试由谁负责
```

例外必须逐点登记：

```text
位置
原因
风险承担者
移除条件
```

按类豁免必须可见、可计数、只降不升。

## 9. 注释简洁

注释只解释：

```text
不变量
边界条件
平台或 API 硬要求
非显然的实现原因
改动会破坏什么
```

禁止：

```text
过程叙述、轮次叙述、历史原因
版本、阶段、演进口吻
对读者叮嘱、设计辩护、方案对比
文件导读、元叙述、待办标记
与当前行为矛盾的旧注释
```

判据：

```text
换一个不了解项目历史的读者来看，这句话是在解释代码，还是在跟他说话
```

## 10. 状态与并发

MUST：

```text
每份可变状态只有一个权威持有者
共享可变状态必须明确同步原语
缓存只能由权威状态派生，并且可以失效
异步响应必须能识别过期结果
操作必须使用发起时的上下文，不读执行时的全局当前值
```

禁止：

```text
UI、服务、存储各自维护一份可变量
无锁读写同一字典、列表或缓存
旧请求覆盖新状态
定时器和订阅没有清理路径
```

## 11. 新增能力检查

### 11.1 新模块

```text
职责一句话
不承担什么
依赖谁
谁依赖它
公开契约
生命周期
失败行为
测试
删除方式
```

### 11.2 新工具或新命令

```text
名称
参数契约
注册点
可见范围
依赖服务
创建者
生命周期
关闭路径
失败返回
负向测试
文档位置
```

条件注册的工具必须写明：

```text
注册条件
默认装配是否提供
未提供时的行为
谁持有生命周期
是否进入公开清单
```

### 11.3 新前端组件或 UI 状态

```text
作用域：进程级、会话级还是页面级
挂载点
数据来源
广播订阅
异步响应保护
卸载与定时器清理
是否操作其他组件
```

## 12. 检查清单

项目应提供等价检查：

```text
依赖方向
层内环
跨层私有导入
核心层具体实现名
静默异常
复杂度阈值
生成文档漂移
配置漂移
测试
覆盖率
秘密扫描
许可证与 NOTICE
构建可重复性
```

工具名不限，判据必须存在。

新增约束必须同时补：

```text
检查
负向用例
文档
```

## 13. 评审报告

每个发现必须给出：

```text
文件与行号
违反的规则编号
调用点或影响面
证据
严重级别
修复边界
```

严重级别：

```text
BLOCKER：契约破坏、状态双写、跨层依赖、静默丢错、未登记资产
MAJOR：职责混杂、边界模糊、失败回滚不完整、关键路径无测试
MINOR：命名、措辞、非关键重复
```

结论：

```text
PASS：无 BLOCKER，检查通过，资产与文档一致
PARTIAL：功能可用，有未验证项或环境阻塞
BLOCKED：任一 MUST 违反、检查失败、归属错误、苟且代码未登记
```

## 14. 红线

```text
不因当前用例方便破坏既有边界
不先加字段再补职责解释
不让门面承担业务规则
不让路由承担业务动作
不让一个组件操作另一个组件的布局
不保留旧入口的再导出和别名层
不让生成物靠手改保持正确
不把未运行说成通过
```
