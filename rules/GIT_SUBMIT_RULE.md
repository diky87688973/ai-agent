# Git提交规则

## P0 级约束（不可越过、不可降级）

### P0-1：提交仓库前必须完成项目复核

**范围**：会改变 GitHub、GitLab 或其他远端仓库状态的动作，包括 `git push`、创建或更新 PR/MR、创建 issue、修改仓库设置，以及会被这些动作推送的本地提交。

**流程**：

1. 按项目复核规则执行复核，读取项目自身声明的适用性。
2. 复核结论必须为 `PASS`；报告中要有命令、退出码、测试结果，并明确未验证项。
3. 只提交目标文件；密钥、真实配置、运行态数据不得入库。

**禁止**：

- 以改动小、时间紧、只是文档为由跳过复核。
- 把读过代码说成已验证通过。
- 先提交、后补复核说明。
- 带着已知问题提交。

**判定**：无法给出复核证据，或结论不是 `PASS`，禁止提交。

### P0-2：提交说明保持简短

**标题**：`type: 一句话说清做了什么`。type 用 `feat` / `fix` / `refactor` / `docs` / `test` / `chore`。不带句号，不超过 30 字。

**正文**：只用 `- ` 短条目，动词开头，一条一个事实，三到六条。不写段落、小标题、推导过程、证据、用例数量或实现原理。

**示例**：

```text
feat: 增加文件卡片展示，重做任务卡与侧边标签
- 增加 present 工具并注册进工具目录
- 增加会话内文件卡片样式与点击预览
- 重做任务卡统计，区分已完成与进行中
- 增加侧边标签样式与面板切换绑定
- 增加本地 JS 事件绑定审计脚本
- 同步文档、单测与 CI 清单
```

**禁止**：

- 禁止条目写成描述句。
- 禁止一条塞多个事实。
- 禁止把问题、改法、验证、证据写成正文小标题。
- 禁止用过程叙述充当正文。

**判定**：标题不符合格式，正文出现段落文字，或条目不以动词开头，即为不合格。
