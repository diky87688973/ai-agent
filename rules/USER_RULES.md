# 用户规则

## P0 级约束（不可越过、不可降级）

### P0-1：提交 GitHub 前必须通过准入检查与工程复核

**适用范围**：任何会改变 GitHub 仓库状态的动作 —— `git push`、创建/更新/关闭 PR、创建 issue、修改仓库设置（topics、release 等），以及会被这些动作一并推送上去的本地提交之前。

**强制流程（三步，顺序不可颠倒，任何一步都不得跳过）**：

1. **准入检查**：确认本次改动范围只覆盖任务相关文件；无顺手重排、无顺手重命名；无密钥与真实配置入库；`.gitignore` 已覆盖且 `git ls-files` 里确实不存在；无未说明的静默吞错；新增的超阈值大文件已登记。
2. **工程复核**：按生产级交付准则逐项核对，结论**必须带证据等级**——已观测（跑过、有输出）、强推定（代码与环境都支持但未运行）、未验证（明确留白）。写明：跑了什么、结果如何、没跑什么、为什么没跑。
3. **通过后才提交**：仅当复核结论为「通过」时，才允许执行提交动作。

**禁止项**：

- 禁止以「改动很小」「时间紧」「只是文档」为由跳过复核。
- 禁止把「读过代码觉得对」表述成「已验证通过」。
- 禁止先提交、后补复核说明。
- 复核中发现的问题，必须先修再重新复核，不得带着已知问题提交。

**判定方式**：若无法给出本次复核的证据（命令输出、退出码、测试结果，或明确声明哪些未验证），视为复核未完成，提交一律不允许。
