# 工程复核详细流程

## 1. 前置

复核前必须取得：

- `production-standards` 正文
- 项目自身声明的适用性申报
- 项目级 `AGENTS.md`、README、架构文档、配置、测试与 CI 定义

标准与流程未加载成功时，不得开始下结论。

## 2. 基线

记录：

- 当前分支
- HEAD 提交
- 远端关系与领先/落后提交数
- 已修改、已删除、已重命名、未跟踪文件
- 生成物、运行态数据、用户数据、缓存是否进入工作区
- 是否存在未提交或未推送内容

工作区基线必须来自实际命令输出，不能凭记忆补全。

## 3. 变更范围

逐文件确认：

- 改动是否属于本次目标
- 是否夹带无关格式化、重排、调试残留
- 是否新增临时旁路、兼容层、重复实现、死代码
- 是否通过改测试、降断言、跳过用例来掩盖失败
- 是否改变了 API、事件、配置键、持久化格式、UI 资产或文档契约

## 4. 检查矩阵

| 编号 | 检查项 | 必查内容 | 阻塞条件 |
|---|---|---|---|
| S1 | 标准基线 | 是否读取并适用标准；不适用项是否申报 | 未读标准、MUST 违反、口头豁免 |
| S2 | 需求与边界 | 目标、非目标、调用方、输入输出、生命周期 | 边界不清导致契约或状态归属错误 |
| S3 | 系统设计 | 组件职责、状态权威源、控制流、数据流、失败路径、取消/重试、幂等 | 双份状态、静默失败、终态不穷尽 |
| S4 | 架构与依赖 | 分层方向、同层环、核心层是否点名具体实现、装配点、扩展点 | 依赖倒挂、循环依赖、核心耦合具体实现 |
| S5 | 契约与数据 | API/事件/配置/落盘格式、最小字段、版本与兼容、只读视图、原子性 | 契约破坏、无版本变更、共享可变状态 |
| S6 | 并发与持久化 | 锁归属、竞态、重复消费、顺序、超时、崩溃恢复、数据完整性 | 状态双写、丢消息、不可恢复写 |
| S7 | 错误与安全 | 失败传播、可读错误、鉴权/信任边界、注入、路径、秘密、依赖安全 | 静默吞错、越权、秘密入库 |
| S8 | 配置与秘密 | 配置键归属、默认值、校验、环境差异、凭据来源、日志脱敏 | 密钥/令牌进入仓库或日志 |
| S9 | 代码质量 | 死代码、调试日志、TODO/FIXME、重复实现、异常捕获、复杂度 | 调试残留、死代码、无依据兼容层 |
| S10 | 代码注释 | 只解释代码、不变量、边界和踩坑；无过程、版本、叮嘱、元叙述 | 过程叙述、对读者讲话、错误注释 |
| S11 | 资产归属 | 源文件、UI、主题、配置、测试、构建产物是否归到真正模块；注册是否单一来源 | 资产错层、重复副本、未注册/孤儿资产 |
| S12 | 文档与文案 | 文档与当前行为、命令、计数、路径一致；无过期、矛盾、歧义 | 文档与代码矛盾、生成文档漂移 |
| S13 | 测试 | 变更行为有测试；失败路径、边界、并发有覆盖；断言有效；无隐性跳过 | 关键行为无测试、测试被弱化 |
| S14 | CI 与门禁 | 本地命令与远端工作流一致；门禁、矩阵、覆盖率、超时、权限 | 工作流漂移、门禁缺失、长期红 |
| S15 | 构建与发布 | 可重复构建、产物清单、版本、依赖锁定、许可证、NOTICE | 不可复现、许可证缺失、产物混入源码 |
| S16 | 仓库与准入 | 大文件、生成物、忽略规则、secret 扫描、分支/提交/推送状态 | 秘密或大数据入库、脏工作区 |
| S17 | 可观测性 | 关键失败是否可见；日志级别、指标、健康检查、错误关联 | 失败不可见、日志泄露敏感信息 |
| S18 | UI/交互 | 状态与按钮一致、外部控制同步、空态/错误态、可访问性、无布局回归 | 交互状态失真、不可操作、明显回归 |
| S19 | 苟且代码 | 死代码、临时旁路、兼容层、重复实现、宽异常、失败当成功、无主资产、未迁移旧路径 | 存在一条无法说明生命周期的苟且实现 |

## 5. 资产归属

先读项目模块设计、职责边界与既有契约，再判断资产归属。

**不属于某个模块的资产，不得加入该模块。**
**职责推导不出的字段，不得新增。**
**职责推导不出的能力，不得对外提供。**

资产包括：

- 源文件、模块、类、函数
- 配置键、默认值、环境变量
- API 字段、事件字段、持久化字段
- 模型工具、工具参数、工具返回值
- 前端脚本、样式、主题、图标、静态资源
- 测试夹具、生成物、运行态数据

判断顺序：

```text
模块职责
→ 资产归属
→ 契约字段
→ 对外能力
→ 唯一注册点
→ 生命周期与失败行为
→ 测试与文档
```

每个新增或移动资产必须回答：

- 为什么必须属于当前模块？
- 其他模块为什么不能拥有它？
- 能否由既有字段派生，因而不新增字段？
- 能否在模块内部完成，因而不新增对外能力？
- 唯一注册点在哪里？
- 是否有重复副本？
- 是否被错误打进发布包、镜像、静态资源清单或测试夹具？
- 缺失、加载失败、卸载时影响谁？
- 是否可以由源重新生成？

红线：

- 不因为当前用例方便把资产塞进相邻模块
- 不先加字段、先加能力，再回头补职责解释
- 不把内部实现细节包装成模型工具、API 或配置项
- 不在壳层放插件私有资产
- 不在核心层放具体业务实现
- 不让同一资产存在两个权威副本
- 不新增无人注册、无人加载、无人负责的孤儿资产
- 不把测试、截图、上下文导出、缓存、临时文件混入源码树

前端资产至少检查：

- 全局主题/壳层样式归壳层，并有统一资源清单
- 插件私有脚本、样式、图标归插件自身
- 新增静态文件有加载路径、缓存策略和缺失时降级
- 构建产物、缓存、截图、临时文件不入库

## 5.1 苟且代码排查

逐项检查，不以测试通过替代：

```text
死代码：无调用点、无注册点、无加载路径
临时旁路：为当前用例绕过既有入口
兼容层：无版本边界、无迁移、无退出条件
重复实现：同一能力两份代码
宽异常：except Exception 把不变量错误转成业务失败
失败当成功：返回 ok=false 但工具/API 仍按成功处理
无主资产：旧路径、旧文件、旧目录无人读写
迁移缺口：落盘路径/格式变更后旧数据不可见
状态越权：缓存、注册表、文件各持一份可变状态
测试专用分支：生产代码为测试留后门
无依据默认值：为让当前用例通过而新增默认
```

每条发现必须给出：

```text
文件与行号
调用点数量
生命周期归属
删除、迁移或保留的理由
```

红线：

```text
“先这样”“只影响当前用例”“以后再说”不是理由
测试通过不能证明没有苟且代码
无法说明谁创建、谁读取、谁清理的资产视为无主
```

## 6. 注释与文案

检查范围：

- 代码注释
- docstring
- 文档
- README
- 配置模板
- 用户可见错误文案

删除或标记：

- 过程叙述、轮次叙述、历史原因
- 版本、阶段、演进口吻
- 对读者叮嘱、设计辩护、方案对比
- 元叙述、文件导读、TODO/FIXME
- 与当前行为矛盾的注释

保留：

- 约束、不变量、边界条件
- 平台/API 硬要求
- 改动会破坏什么
- 非显然实现原因

执行：

1. 跑项目文案门禁
2. 对改动文件与相关文档逐项人工检查
3. 扫描全项目文档；生成文档只检查生成器
4. 违例按规则清洗；清洗不改变行为
5. 报告写明检查范围、门禁结果、清洗数量、未覆盖文档与剩余风险

## 7. 测试与 CI

- 先跑受影响测试和静态检查
- 用户要求复核时跑项目定义的全量 CI
- 使用项目自己的 CI 入口，不手拼步骤替代
- 记录通过、失败、跳过数量
- 跳过必须有环境原因
- 覆盖率按项目配置执行；没有数据时明确标注
- 检查远端工作流与本地门禁是否一致
- 检查工作流权限、缓存、超时、secret 注入、矩阵

## 8. 结论

### PASS

- 无 `BLOCKER`
- 全量 CI 通过，或仅存在规则允许的环境跳过
- 文档、测试、资产归属一致
- 工作区无未申报的运行态数据或用户数据

### PARTIAL

- 功能本身可用
- 存在未验证项或环境阻塞
- 没有足以否定交付的 `BLOCKER`

### BLOCKED

任一成立：

- 违反标准 `MUST`
- 构建、测试、静态检查失败
- 覆盖率或项目硬门禁失败
- 秘密、用户数据、运行态数据进入仓库或日志
- 双份权威状态、跨层依赖、契约破坏
- 资产错层、未注册、重复副本
- 存在未登记的死代码、临时旁路、兼容层或旧路径孤儿
- 新增了职责范围外的字段、配置键、模型工具、API 或对外能力
- 关键行为无测试且风险不可接受
- 工作区存在未申报的高风险生成物
- 远端 CI 与本地门禁漂移

### 严重级别

| 级别 | 含义 |
|---|---|
| `BLOCKER` | 阻止准入，必须修复或明确阻塞 |
| `MAJOR` | 明显偏离标准，有实际风险 |
| `MINOR` | 命名、措辞、格式、非关键清理项 |

## 10. 证据

- UI、交互、视觉、任务状态：实际页面截图
- 代码、配置、事件、接口：文件路径与行号
- 命令、门禁、CI：命令、原始结果、数量
- 文档：文件路径、段落或生成器校验结果

无法截图或无法复核时，写入“未验证”，不得用推测代替结论。

## 11. 修复与复验

- 只修与核查目标相关的问题
- 修改前备份
- 批量替换逐文件语法校验，失败不写回
- 修复后重跑受影响测试、静态检查和必要的全量 CI
- 修复资产归属后重新核对资源清单、构建产物、发布包
- 测试数据、进程、临时目录当场清理

## 12. 禁止项

- 不把未运行写成通过
- 不用“应该”“大概”“看起来”代替证据
- 不以历史原因、先这样、只影响当前用例为由绕过 `MUST`
- 不增加无依据的兼容层、旁路或临时开关
- 不删除用户数据、运行态数据、会话记录或凭据
- 不未经授权 commit、push、改远端或动生产配置
